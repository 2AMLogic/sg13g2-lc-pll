# prescaler-div89 diagnosis 20261110-168-rl-bisection (issue #168)

**Result (simulated, not measured): the 5.5 GHz SLOW (hbt_wcs + res_wcs) / 125 C failure of `20261109-234530-6fbbf0e-pdk-resistors.md` is caused by the value of the latch load resistors `XRL1/XRL2` (rppd 1u x 9.05u) inside `cml_latch` as used by `cml_dff` in `cml_div23` (the first stage, running at the VCO frequency). At res_wcs / 125 C they are 2673 ohm against 2400 ohm nominal (+11 %). The parasitic capacitance of the PDK resistor model is not the cause. Nothing was resized and no spec row was changed.**

- **Scope of the experiment**: one corner, SLOW / 125 C / 2.970 V / 5.5 GHz, MC low (/8 expected) and MC high (/9 expected), graded as in the parent record (rising zero crossings of v(OUTP)-v(OUTN) from 6 ns, period / T_in; pass = 8.00 +-0.25 and 9.00 +-0.25 on every period). 2 units per variant, 18 variants plus the baseline reproduction. Every other corner is untouched by this record.
- **Netlist under test**: `design/netlist/prescaler.spice` at `83c2243` (sha256 of the unmodified file is in the parent record, `41c32b6c...`). Variants are copies in scratch directories, generated by `gen_vars.py` (this directory; paths in it are the scratch paths used on the run); a "nom" variant replaces the named rppd class by an ideal `R` of the pre-#164 value (RL 2400, RT 1200, RTC 2400, RF 2400, RDF 4000, RIN 20k, RD1 12k, RD2 28k); a "wcs125" variant uses the value of the same geometry at res_wcs / 125 C from `rppd_extract.py`. The three instance-level variants (`latch_*`) were made by an inline edit not kept in `gen_vars.py`: a copy of `cml_latch` named `cml_latchi` with `XRL1/XRL2` replaced by ideal `R` of the stated value, and the latch instances of one parent subckt (`cml_dff` or `div2_cml_ls`; or both, for `latch_all_*`) pointed at it.
- **Method**: PDK rppd/rhigh via r3_cmc OSDI, per-process sections as in `div89_chain.request.json`; the requests are single-corner copies of it. Run with `klt sim --batch-set ... --max-in-flight 4 --wait-for-capacity 600` on the Spot batch fleet (jobs below); the baseline was also reproduced by one local single-corner `klt sim --backend local` run (ratio 10.00, MC low, the same as the fleet). Fleet and local ngspice is 46 against sim/pins.json pin 47 (known mismatch, same as the parent record).
- **rppd value check** (`rppd_extract.py`, one DC op per section / temperature, 0.1 V): 1u x 9.05u = 2395 (typ, 27 C), 2436 (typ, 125 C), 2628 (wcs, 27 C), **2673.5 (wcs, 125 C)**, 2163 (bcs, 27 C), 2199 (bcs, 125 C) ohm. The other geometries scale the same way (2u x 9.05u RT 1344.5 at wcs/125 C against 1200 ideal).

## Reading

1. **Which resistor / node**: `XRL1/XRL2` of `cml_latch` as instantiated in `cml_dff` (`XF1/XF2` of `cml_div23`), i.e. the load of the master/slave latches of the two flip-flops that make up the /2-/3 first stage. Restoring only those four resistors to 2400 ohm restores /8 and /9 (`latch_ideal_dff`); restoring the /2 stages' latches, the AND-gate loads (`cml_and2`), the tail / tail-cascode (`XRT`, `XRTC`), the emitter followers or the bias network does not.
2. **Value, not parasitic C**: with the PDK parasitic C removed (an ideal `R` at the res_wcs / 125 C value, `RL_wcs125`, `RL_wcs125_latch`) the failure is reproduced. The issue's "likely cause: rppd sheet R and its parasitic C" is half right: the sheet-R spread (+11 % at res_wcs / 125 C) is the cause; the parasitic C is not needed to reproduce it. A separate "PDK model, parasitic C only" variant was not run (not needed to answer the question; not claimed).
3. **Margin**: with ideal latch loads the first stage divides correctly at 2400 and not at 2500 (/8 8.02..8.95 fails by the +-0.25 rule) at this corner. The failing PDK value is 2673. The grid passes at TYP / 125 C (2436) and at SLOW / 27 C (2628), so the usable latch-load range at 5.5 GHz / 2.97 V is narrow and at its edge at res_wcs.
4. **Not established**: the waveform node that stalls (no internal-node waveform was saved or inspected); the exact threshold between 2400 and 2500; whether the mechanism is swing (load R x tail current) or the RC at the latch output; behaviour at 3.30 / 3.63 V (they failed in the parent record at SLOW / 125 C too, and are not re-run here); the async (MC toggle) case. All of these would be checked by the grid re-run that any fix needs.

## Proposed fix (not implemented here)

- Reduce the nominal geometry of the `cml_latch` load rppd so that its res_wcs / 125 C value is at or below about 2400-2450 ohm (rppd 1u x 9.05u is 2673 there; scaling the length by ~0.9 gives ~2410 at wcs/125 C and ~1980 at bcs/27 C by the extracted values above, which lowers the output swing and raises tail-current-dependent Vce stress at FAST, so #165 and the VCO-load check #160 must be re-run). This is a resize of `design/cml_latch.sch` and is a follow-up issue / PR; it is not in this change.
- The /8 and /9 5.0 GHz and the other 5.5 GHz corners are *not shown unaffected* by that resize here; the 108-unit chain grid and the 288-unit async grid via `klt sim` are required after it, and `layout/` cell work (#58) is invalidated by a resize.
- If no resize closes SLOW / 125 C at 5.5 GHz, the alternative is a spec decision record under `spec/decision-records/` (DR numbering after DR-005) for the stretch-band ceiling; row 1/4 is not relaxed by this record.
