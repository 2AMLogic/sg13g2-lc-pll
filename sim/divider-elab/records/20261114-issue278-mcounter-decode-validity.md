# M/A counter state sequence and terminal-count decode validity 20261114 (issue #278)

**Result (logic-level, not simulated and not measured): the `mcounter` terminal-count decode `DT` as drawn in `design/netlist/divider.spice` decodes the single state Q = 0010 - count 2, q0 = LSB - not the count 1 that `design/README.md` states; the M counter loads the M code and counts DOWN through count 2 to count 1, where the registered reload (`TC2`) fires; and for every N in 90-110 (only M codes 11, 12 and 13 occur) the pre-terminal state count 3 is visited exactly once per output period, immediately before count 2, with no load landing on count 2 or count 3. #199's remaining structural option - decode count 3 one count early and register it - is logic-valid across the whole target window. It breaks at M codes 2 and 3, neither reachable in the window (spec row 3 requires M >= 7).**

- **Scope**: `mcounter` (`design/netlist/divider.spice:61-122`) and `acounter` (:128-164) as drawn at `cd87520`, enumerated jointly for every N in 90-110 at `N = 8*M + A` (spec row 3). No schematic, netlist or spec file was changed; the netlist is read only.
- **Method**: `sim/divider-elab/counter_state_model.py` parses the two `.subckt` instance lists out of the committed netlist and evaluates them as a synchronous zero-delay boolean model: gates `inv_hv`/`nand2_hv`/`nand3_hv`/`nor2_hv`, flops `dff_tg_hv` (D CK Q) and `dff_tg_hv_qn` (D CK Q QN, QN the complementary output); every flop latches its settled D network at the same CKL edge (q0-q3, borrow flags b1-b3, TC/TCN/TC2; s0-s2, MC). The model free-runs from the all-zero power-on state and detects the limit cycle by joint-state repeat, then rotates it to start at the state the reload lands on. No PDK, no ngspice, no `klt sim`, no timing: this is a logic-level result and must not be quoted as a timing result.
- **Decode, derived not typed**: evaluating the parsed `XT1..XT4` network over all 16 q states (`f32 = NOR2(q3,q2)`, `g10 = NOR2(q0,q1n)`, `DTN = NAND2(f32,g10)`, `DT = INV(DTN)`) asserts `DT` for exactly one state, `(q3,q2,q1,q0) = 0010`, registered one CKL cycle later into `TC`/`TCN`/`TC2` (`XFT`/`XFTN`/`XFT2`).

## Correction appended 2026-11-15 (issue #297): the "README discrepancy" above is withdrawn

The finding at line 8 above ("README discrepancy (found, not fixed here)") and the one comparison clause inside the line-3 bolded Result ("- not the count 1 that `design/README.md` states") are **withdrawn**: both compare the README's `Q = 0001` statements against `DT`'s phase and report a disagreement that does not exist. Every other clause of lines 3-18 stands as written, including the `DT`-decodes-count-2 derivation, the down-count sequences and the #199 look-ahead analysis; this appendix adds text and changes nothing above it (append-only, additions only).

The two phases the comparison conflated: `DT` is the **combinational** decode (`XT1..XT4`), asserted during the count-2 cycle at `Q = 0010`; `TC`/`TCN`/`TC2` are the **registered** outputs (`XFT`/`XFTN`/`XFT2` = DFF(`DT`)), high one CKL cycle later during the count-1 cycle at `Q = 0001`, where `TC2` gates the `M[3:0]` load mux. A registered terminal count fires its flop outputs one clock after the decode asserts - which is exactly what the README describes. So `design/README.md:147` ("loads `M[3:0]` when Q = 0001") and `:181` ("`TC`/`TCN` are flop outputs, high exactly when Q = 0001") are **correct as written**, and both were already confirmed by this record's own earlier lines: line 3 ("counts DOWN through count 2 to count 1, where the registered reload (`TC2`) fires") and line 7 ("registered one CKL cycle later into `TC`/`TCN`/`TC2`"). `design/README.md` is not edited by #297 beyond one disambiguating clause at `:147` naming both phases; the decode itself and any gate-level change remain #199's.

Method, stated next to the numbers: re-evaluated the committed `.subckt mcounter` of `design/netlist/divider.spice` with `sim/divider-elab/counter_state_model.py`'s own parser and zero-delay model over the full limit cycle for every M code the target window reaches (M = 11, 12 and 13 - identical for all three): `DT` high at count 2 (`Q = 0010`, one state per period), `TC` and `TC2` each high at count 1 (`Q = 0001`, one snapshot each per period), the state following `Q = 0001` the loaded M code. Logic-level, zero-delay: no PDK, no ngspice, no `klt sim`, no timing - not a measured or timing result. The phase separation is now asserted mechanically by `test_dt_registered_phase_separation` in `sim/divider-elab/test_counter_state_model.py` (issue #297), so this conflation is caught by the suite rather than by review.
