# Trial: TC and TC2 from their own flops fed by DTN plus an inverter each makes FAST 125 C 2.97 V stop dividing (2026-11-05, base `6aec713`, issue #97)

**Result (simulated, not measured): NEGATIVE. The change was not kept; no design file is changed in this increment.** After `20261105-issue97-tc-from-tcn-inverter-trial.md` (decoding `TC` from `TCN` rejected), this separates the two things that trial changed. `XFT` and `XFT2` stay as dedicated flops but take D from `DTN` (the wider pulse that `XFTN` captures) instead of `DT`; their outputs `tcb`/`tc2b` go through one `inv_hv` each (`XTC1`, `XTC2`) to `TC`/`TC2`; `XT4` (DTN -> DT) is removed. `TCN` gains no load. Patch: `20261105-issue97-tc-own-flops-from-dtn-trial.patch` (`design/mcounter.sch` + `design/netlist/divider.spice` regenerated by `design/netlist.sh divider` through `klt netlist`; the tool also added a `klt-netlist-inputs` stamp line).

## Method
Four single-corner stage-2 requests (`request-stage2-97-s-*`, ramped start-up, unchanged, `tran 4p 120n`; "divides" = `tfb` 58.5-61.5 ns) submitted with `klt sim --batch-set ... --backend batch` (jobs `klt-sim-33d49d2775d8`, `klt-sim-dd05e3543596`, `klt-sim-ad9fe38f3fc3`, `klt-sim-bc1b7e57f6e9`). ngspice 46 on the fleet against the pin of 47 (`sim/pins.json`): the pin is not met; nothing ran locally. One run per corner, repeatability not shown. Raw: `20261105-issue97-tc-own-flops-from-dtn-trial-measurements.json`.

## Result
| corner | `tfb` | `fbmax` (V) | reading |
|---|---|---|---|
| TYP 125 C 2.97 V | not reached | 0.0014 | FB never rises: does not divide (as before) |
| SLOW 125 C 2.97 V | not reached | 0.0013 | does not divide (as before) |
| FAST 125 C 2.97 V | not reached | 0.0015 | **regression**: divided on the in-tree netlist |
| TYP 125 C 3.63 V | 59.997 ns | 3.72 | divides (as on the in-tree netlist) |

All four converged. Of these four corners the in-tree netlist divided two (FAST 125 C 2.97 V and TYP 125 C 3.63 V); this change divides one, so it loses one. The other 14 corners were not re-run.

## Reading
- Feeding the TC flops from `DTN` does not rescue TYP 125 C 2.97 V, so the `DT` pulse width (0.74 ns vs 1.79 ns for `DTN`) is not by itself the cause of the TYP miss; that contradicts the candidate in `20261105-issue97-tc-chain-two-125c-corners.md`. No per-node trace was taken here, so the real mechanism is still not shown.
- FAST 125 C 2.97 V depended on the in-tree `DT` path or on the `XT4` load on `DTN`; with it removed it stops dividing. The `TC` consumers see the terminal count one inverter later than a direct flop output, which looks to be what the cycle cannot absorb at 125 C (inferred from outcome, not probed). Both TC-via-inverter trials fail the same way.
- Rejected as a fix: any variant that inserts an inverter between the TC flop and its consumers.
